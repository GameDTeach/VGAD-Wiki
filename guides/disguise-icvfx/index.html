Disguise ICVFX Workflow

The XR workflow with Unreal Engine and Disguise Designer, concentrating on what you set up inside Unreal.

Two halves: get Unreal ready, then point Disguise at it. Do them in that order — Disguise can't configure a RenderStream asset that Unreal hasn't produced yet.

1

What you need

Two machines at minimum, and a project that is ready to be pushed hard.

  • A computer running Unreal Engine
  • A computer running Disguise Designer
Optimise your project first

Do this before you touch RenderStream or Multi-User. Once the wall is live you are rendering the scene several times over — once for the inner frustum, once for the outer, once for the mesh — so anything expensive gets multiplied.

Coming back to optimise afterwards means redoing settings work, because performance problems look like configuration problems and you'll waste a session chasing the wrong thing.

Machine addresses

You'll be asked for these more than once.

Machine Role IP address
FS-BB1 Editor 10.10.10.35
FS-BB2 Editor 10.10.10.36
FS-BB3 Editor 10.10.10.37
Render server Runs the copied project 10.10.10.201
FS-BB4 Multi-User session host [IP not recorded]
Two gaps worth closing

FS-BB4 appears in the Disguise settings as the session host, but has no address in the source document. Add it above once you've checked.

The nDisplay guide writes these machines with underscores — FS_BB1 — and this workflow uses hyphens. Same machines. Worth settling on one spelling across the studio.

2

Install the RenderStream plugin

RenderStream is how Disguise gets frames out of Unreal. It goes into the project, not the engine.

  1. In your Unreal project folder, create a folder called Plugins if there isn't one.
  2. Go to github.com/disguise-one/RenderStream-UE/releases.
  3. Find the release that matches your version of Unreal and download it.
  4. Extract the zip into the Plugins folder.

The result should look like this. One folder between the project and the plugin's own files — no more, no less.

UE5_Project_Name/
└── Plugins/
    └── RenderStream-UE/        ← the plugin's files sit directly in here
        ├── Source/
        ├── Resources/
        └── RenderStream.uplugin
Get it from the source, not from another project

Always download from GitHub or copy from a known master version. Copying the plugin out of another Unreal project is how you end up running a build made for a different engine version, which fails in ways that look like configuration errors.

  1. Open the Unreal project and go to Edit → Plugins.
  2. Enable Disguise RenderStream. While you're there, enable Multi-User Editing too — you'll need it in Part 6 and this saves a second restart.
  3. Restart the Unreal editor.
3

RenderStream project settings

Two settings, both under Edit → Project Settings.

  1. Under Maps & Modes, set both Editor Startup Map and Game Default Map to your main VP environment map.
  2. Under Plugins → Disguise RenderStream, set Scene Selection to Maps.
4

Build the camera rig

Two cameras in exactly the same place, parented to one actor. Disguise treats them as separate channels.

The inner frustum is the high-quality region the camera is actually looking at. The outer frustum fills the rest of the wall, so what spills past the camera still lights the set and reflects off anything shiny. That's why they render at different quality later.

  1. In your main map, create two Cine Camera Actors.
  2. Name them exactly inner frustum and outer frustum.
  3. Place them at the same location.
  4. Create an Empty Actor and position it at that same point.
  5. In the Outliner, drag both cameras onto the empty actor so they become its children.
  6. Save All.
The names travel

You'll pick these cameras by name in Part 11 when you set up channel mappings in Disguise. Rename them later and the mappings stop matching.

5

Point Unreal at this machine

Multi-User talks over UDP, and each machine has to announce its own address.

  1. Go to Edit → Project Settings → UDP Messaging.
  2. Set Unicast Endpoint to the IP of the machine you are sitting at — see the table in Part 1.
  3. Click Set as Default and accept the pop-ups.
This one is per machine

Every machine needs its own address here, including the render server in Part 8. Copying the project without changing this is the most common reason a machine silently fails to join the session.

6

Multi-User settings

Still in Project Settings, under Multi-User Editing.

Setting Value
Multi-User Toolbar Enabled
Auto Connect and Auto Retry Disabled
Default Server URL 10.10.10.35 — whichever machine hosts the session
Default Session Name Anything, but lowercase and named after the production
  1. Click Set as Default and accept the pop-ups.
Why auto-connect is off

It was turned off during testing to stop Unreal repeatedly trying to join a session that didn't exist yet, which makes startup problems much harder to read.

Once the studio workflow is settled it's reasonable to turn it back on.

7

Host the session

Done on the hosting machine — in Futures Studio, usually the one furthest left.

  1. Open the Multi-User Browser.
  2. Launch a server.
  3. Create a new session. Keep the name short, and make it exactly what you typed as the default session name in Part 6.
  4. Connect the host to its own session.
  5. If that all works, save the project and close Unreal.
The name has to match in three places

The session name appears in the Multi-User settings, in the session you create here, and again in the Disguise engine settings in Part 9. A mismatch in any one of them means Disguise joins nothing, with no obvious error.

8

Copy the project to the render server

The render server runs its own copy, and Multi-User will only sync copies that match.

  1. With Unreal closed, copy the full Unreal project to the render server.
  2. Open the copied project and go to Edit → Project Settings → UDP Messaging.
  3. Change Unicast Endpoint to the render server's own address, 10.10.10.201.
Identical means identical

Multi-User compares the projects. A stray asset, a different plugin version or a half-copied folder will stop the session syncing.

The unicast endpoint in step 3 is the one deliberate difference — every machine announces its own address.

9

Add the RenderStream layer

Over to Disguise Designer. From here you're telling Disguise where to find Unreal and how to talk to it.

  1. Add a new track. The convention is to name it after the scene.
  2. Add a RenderStream video layer to the timeline — Ctrl + L.
  3. Select the layer, then right-click on workload to configure it.
  4. Click Add asset.
  5. Filter by Unreal and select your Unreal project.
Project not in the list?

Disguise only sees projects inside its RenderStream project folder, which defaults to C:\Documents. If yours isn't showing, it's in the wrong place.

Engine settings

  1. Right-click the asset and choose Edit engine settings.
Setting Value
Enable Multi-User Edit Enabled
Multi-User Session Name The session name from Part 7
Multi-User Session Host FS-BB4
Enable Unreal Window Disabled — this would open Unreal full screen
10

Cluster pool and assigner

The pool is the set of machines that will render. The assigner decides how work is divided and how frames travel.

  1. Create a cluster pool and name it uepool.
  2. Add the render machine to it — the RXiii.
  3. Set up the default assigner with the values below.
Setting Value
Splitting strategy Full frame
Transport format RGB 4:4:4 8 bit
Scale factor 1
Preferred network MEDIA — 10.10.10.255
11

Channel mappings

The channels are the cameras you made in Part 4. This is where the inner and outer frustum get different amounts of effort.

Inner frustum

  1. Select inner frustum.
  2. Set mapping to mrset (backplate).
  3. Set load weight to 1.0.

Outer frustum

  1. Select outer frustum.
  2. Set load weight to 0.2.

Mesh

  1. Add a new mapping and name it mesh.
  2. Select geometric / mesh.
  3. Set mapping res scale to 0.2.
  4. Set render res scale to 0.2.
Why the weights differ

The inner frustum is what the camera actually records, so it gets full effort. The outer frustum and the mesh only provide lighting and reflections, which nobody sees at full resolution — so they run at a fifth of the load and leave headroom for the part that matters.

12

Add the screen and start

Last step — tell Disguise which surface the camera is looking at, then run it.

  1. Add a screen, name it wall, and set its type to LED screen.
  2. In the scene, open the camera options.
  3. Expand the hierarchy, click Add child, and select wall.
  4. Click Start to begin RenderStream from the Unreal project.
What good looks like

Disguise launches Unreal on the render machine by itself and starts pulling frames. The wall shows your environment, and moving the camera in Unreal moves the view on the wall.

If nothing appears, work backwards through the three places the session name has to match — Part 6, Part 7 and Part 9. That is almost always where it has gone wrong.
