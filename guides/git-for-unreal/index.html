Git and GitHub for your Unreal project

This term your Unreal project lives on GitHub instead of a network drive. This guide takes you from no account at all to your first upload, one click at a time.

You don’t need any coding or Git experience. Set aside about an hour for the first time through, and tick each part off as you finish it.

1

The five words you need

Git has a lot of jargon. For this module you only need these.

Git keeps a history of your project, like save points in a game. GitHub is a website that stores that history online, like cloud saves. GitHub Desktop is the app you’ll click buttons in, so you never have to type Git commands.

Word What it means Game equivalent
Repository (repo) Your project folder, plus Git’s record of every save you’ve made in it. Your save file slot
Commit A snapshot of your project at one moment, with a short note describing what changed. Making a save point
Push Upload your new commits to GitHub. Syncing to the cloud
Pull Download commits from GitHub onto the computer you’re using. Loading your cloud save on another console
Clone Download a whole repository onto a computer for the first time. Installing the game and your save on a new machine

A commit only exists on the computer you made it on until you push it. If you commit but forget to push, your work is not backed up.

2

Create a GitHub account

About 10 minutes. You’ll keep this account after you graduate, so treat it as your professional one.

  1. Go to github.com/signup.
  2. Enter an email address. Use your rhul email address.
  3. Create a strong password.
  4. Choose a username. Future employers may see it, so something like alex-morgan-games is better than xXsniperXx. Letters, numbers and single hyphens only.
  5. Complete the puzzle check, then enter the code GitHub emails you.
  6. If GitHub asks questions about how you’ll use it, you can skip them. Choose the Free plan if asked.

Turn on two-factor authentication

GitHub requires this for accounts that upload work, so do it now rather than being locked out mid-term.

  1. Install an authenticator app on your phone, such as Microsoft Authenticator or Google Authenticator.
  2. On GitHub, click your profile picture (top right), then Settings, then Password and authentication.
  3. Click Enable two-factor authentication and scan the QR code with your authenticator app.
  4. GitHub shows you recovery codes. Download them and keep them somewhere safe that isn’t your phone. If you lose your phone, these codes are the only way back into your account.

Keep your email address private

Every commit records an email address, and that record is permanent. If you ever make a repository public, or add someone to it, your real address travels with it. GitHub can give you a forwarding address to use instead.

  1. Click your profile picture (top right), then Settings, then Emails.
  2. Tick Keep my email addresses private.
  3. Tick Block command line pushes that expose my email.
  4. GitHub shows you an address ending in @users.noreply.github.com. You don’t need to write it down. GitHub Desktop picks it up on its own in Part 4.
Do this before Part 4

If you install GitHub Desktop first, it will already have stored your real address and you’ll have to change it by hand.

Optional, but worth it! Apply for the free GitHub Student Developer Pack at education.github.com/pack.
3

Install Git

About 5 minutes. The class computers already have this. Do it on your own computer.

On Windows

  1. Go to git-scm.com/downloads/win and download the 64-bit installer (the top link).
  2. Run the installer. It asks a lot of questions. Leave every option as it is and keep clicking Next, then Install.
  3. When it finishes, untick “View Release Notes” and click Finish.

This also installs Git LFS (Large File Storage). Unreal files like .uasset and .umap are big, and Git LFS is what lets GitHub store them properly. You need to switch it on once:

  1. Open the Start menu, type Git Bash and open it. A black window appears.
  2. Type git lfs install and press Enter.
  3. Close the window.
Check it worked

The window should reply with Git LFS initialized. If it says “command not found”, restart your computer and try again.

On a Mac

  1. Open Terminal (press Cmd + Space and type Terminal).
  2. Type git --version and press Enter. If Git isn’t installed, your Mac offers to install the “command line developer tools”. Click Install and wait.
  3. GitHub Desktop (next part) includes Git LFS, so you don’t need anything else for this module.
4

Install GitHub Desktop

About 5 minutes. This is the app you’ll use every lesson.

  1. Go to desktop.github.com, download it and run the installer. It opens by itself when done.
  2. Click Sign in to GitHub.com. Your web browser opens. Sign in, then click Authorize desktop and allow the browser to open GitHub Desktop.
  3. On the Configure Git screen, check the Email box shows an address ending in @users.noreply.github.com. If it shows your real address instead, go back and do the email privacy step in Part 2, then sign out and in again. Click Finish.
On a class computer

Sign out when you leave: File → Options → Accounts → Sign out. Otherwise the next person could push to your account.

5

Make your project repository

About 5 minutes. Your lecturer has made a starter repository with the right settings for Unreal already in it. You’ll make your own copy.

  1. Open the starter repository: Unreal Template Repository.
  2. Click the green Use this template button, then Create a new repository.
  3. Make sure Owner is your username.
  4. For Repository name, use GameBuild2D_yourfullname. No spaces.
  5. Choose Private.
  6. Click Create repository.
If GitHub ever emails you about storage

Forward it to vgadlecturers@rhul.ac.uk straight away. It means something larger than expected has gone into your project, and it is far easier to deal with in the week it happens than at the end of term.

Give your lecturer access

  1. On your new repository’s page, click Settings (the tab along the top), then Collaborators.
  2. Click Add people and enter GameDTeach.
Check it worked

Your repository page should list two files: .gitignore and .gitattributes. These tell Git which Unreal folders to skip and which files are large. Don’t delete or edit them.

6

Download repo to your computer

About 2 minutes. This is called cloning.

Where to put it matters

Create a folder called C:\UnrealProjects (on a Mac, a folder called UnrealProjects in your home folder) and keep all your projects there.

Do not use EditShare or your Desktop, Documents, OneDrive, iCloud or any network drives. Cloud-syncing folders fight with Git and Unreal, and projects get corrupted.

  1. In GitHub Desktop, click File → Clone repository.
  2. On the GitHub.com tab, click your new repository in the list.
  3. Next to Local path, click Choose… and pick your UnrealProjects folder. GitHub Desktop adds the repository name on the end for you.
  4. Click Clone.
  5. If GitHub Desktop asks to Initialize Git LFS, click Initialize Git LFS.
Check it worked

Click Repository → Show in Explorer (Show in Finder on a Mac). You should see a folder containing .gitignore and .gitattributes. On a Mac these are hidden; press Cmd + Shift + . to show them.

7

Put your Unreal project inside your repo

About 10 minutes. You’ll make a normal Unreal project, then move it into your repository folder.

Make the project

  1. Open Unreal Engine 5.7 from the Epic Games Launcher.
  2. Choose New Project → Games → Blank.
  3. Under Project Defaults choose BLUEPRINT - leave the other two options as default.
  4. Set Project Location to a temporary place, such as Documents or Desktop.
  5. Give your project a short name with no spaces, such as GameBuild2D, and click Create.
  6. When the editor has fully opened, close Unreal.

Move it into your repository

  1. Open the project folder Unreal just made in your Documents or Desktop. You’ll see folders like Config and Content, and a file ending in .uproject.
  2. Select everything inside it (Ctrl + A, or Cmd + A on a Mac) and copy it (Ctrl + C, or Cmd + C on a Mac).
  3. Open your repository folder in UnrealProjects and paste (Ctrl + V, or Cmd + V on a Mac).

Your repository folder should now look like this. The .uproject file must sit right next to .gitignore, not inside another folder.

UnrealProjects/
└── GameBuild2D_JohnRomero/        ← your repository folder
    ├── .gitattributes
    ├── .gitignore
    ├── Config/
    ├── Content/
    ├── DerivedDataCache/          (skipped by Git, that’s fine)
    ├── Intermediate/              (skipped by Git, that’s fine)
    ├── Saved/                     (skipped by Git, that’s fine)
    └── GameBuild2D.uproject        ← right here, next to .gitignore
Common mistake

If you dragged the whole project folder in, you’ll have GameBuild2D_JohnRomero/GameBuild2D/GameBuild2D.uproject. Open that inner folder, move everything up one level, and delete the empty folder.

  1. Double-click the .uproject file in your repository folder to check the project opens.
  2. Leave the Desktop copy for now. You’ll delete it once your first push has worked in Part 9.
8

Git and Unreal working together

A few habits and one optional setting.

Always open the right copy

Unreal’s project browser remembers the Desktop copy too. From now on, open your project by double-clicking the .uproject in your repository folder. After your first push, delete the Desktop copy so you can’t open the wrong one by accident.

Save before you commit, close before you pull

Git can only save what Unreal has written to disk. Before committing, use File → Save All (Ctrl + Shift + S). Before pulling changes down, close Unreal completely, because the editor holds files open and gets confused when they change underneath it.

Optional: show Git status icons inside Unreal

Only do this if your lecturer asks you to. It adds small icons to assets in the Content Browser so you can see what has changed since your last commit.

  1. With your project open, click Revision Control in the bottom-right corner of the editor, then Connect to Revision Control…
  2. Set Provider to Git.
  3. Check the Git path is filled in (on Windows it’s usually C:/Program Files/Git/bin/git.exe) and that it has found your repository.
  4. Click Accept Settings.

Even with this turned on, do your commits and pushes in GitHub Desktop, not with Unreal’s Submit button, so there’s only one way of doing things.

Now close Unreal

9

Your first commit and push

About 5 minutes, depending on your internet speed.

  1. Make sure Unreal is closed.
  2. In GitHub Desktop, check the Current repository box at the top left shows your repository.
  3. The Changes tab on the left lists every new file. Scroll through it and check what’s there (see below).
  4. At the bottom left, type a short message in the Summary box: Initial Unreal project.
  5. Click Commit to main. You’ve made your first save point.
  6. Click Push origin at the top. This uploads it. It may take a few minutes the first time.
  7. Click the History tab on the left. Your commit is listed with a name against it. Check that name is yours — on a shared computer it can be left over from whoever used it last.
Before you click Commit, check the list

You should see files starting with Config/, Content/ and your .uproject.

You should not see anything starting with Saved/, Intermediate/ or DerivedDataCache/. If you do, your project isn’t sitting next to .gitignore. Go back to Part 7 and fix the folder layout before committing.

Check it worked

Open your repository on github.com and refresh the page. You should see your Config and Content folders.

Click into Content and open any .uasset file. GitHub should say Stored with Git LFS. If it does, everything is set up correctly and you can delete the Desktop copy of your project.

10

Your routine every lesson

This is what replaces copying your project to the network drive.

At the start

  1. Open GitHub Desktop and pick your repository.
  2. Click Fetch origin.
  3. If the button changes to Pull origin, click it.
  4. Now open your project in Unreal.

At the end

  1. In Unreal, File → Save All, then close Unreal.
  2. In GitHub Desktop, write a summary and click Commit to main.
  3. Click Push origin and wait until it finishes.
  4. On a class computer, sign out of GitHub Desktop.

Pull before you start and push before you leave, and your project is the same wherever you pick it up. If you forget to pull, you’ll be working on an old version.

First time on a new computer

If a computer doesn’t have your project yet (your laptop at home, or a different class machine), repeat Part 6 to clone it. You don’t need to redo anything else.

Commit more often than once a lesson

Commit whenever you finish something that works, like a save point before a boss fight. If you break something later, you can go back. A good summary says what you did:

Helpful Unhelpful
Door opens when ball reaches switch stuff
Blockout for room 2 update
Imported funnel mesh and materials asdfgh

Source art is different

If you keep exported models, textures or audio in the project, commit them when a piece is finished rather than at every save. Git stores a complete new copy of a large file each time it changes, not just the part that changed, so ten saved versions of one model take ten times the room against your account’s allowance.

Get the lecturer’s demo project

Your lecturer’s example project is also on GitHub, and gets updated as the term goes on.

The first time

  1. Open Unreal Project Demo Repository. note: you must log into github for this to work.
  2. Click the green Code button, then Open with GitHub Desktop.
  3. Set the local path to your UnrealProjects folder and click Clone.

It sits next to your own project, as a separate folder. Never put it inside your project folder.

UnrealProjects/
├── GameBuild2D_JohnRomero/         ← your work (you push to this)
└── GameBuild2D_LecturerDemo/       ← lecturer’s demo (you only pull this)

Getting each week’s update

  1. Close the demo project in Unreal if it’s open.
  2. In GitHub Desktop, change Current repository to the demo.
  3. Click Fetch origin, then Pull origin.
Look, don’t edit

Treat the demo as read-only. You can’t push to it, and any changes you make will get in the way when you pull the next update.

If you experimented in it anyway, right-click the changed files in the Changes tab and choose Discard changes before pulling.

To use something from the demo in your own game, right-click the asset in Unreal’s Content Browser, choose Asset Actions → Migrate, and pick your own project’s Content folder.

12

If something goes wrong

Click a problem to see the fix. If none of these match, take a screenshot and ask in class before trying anything drastic.

Push fails with “Updates were rejected” or “newer commits on remote”

GitHub has commits this computer doesn’t, usually because you worked somewhere else and forgot to pull here first. Close Unreal, click Pull origin, then Push origin again.

A file “exceeds GitHub’s file size limit of 100 MB”

Something big isn’t covered by Git LFS, often a video, a large audio file or a Maya scene. Don’t keep trying to push.

If you haven’t pushed yet, open the History tab, right-click your latest commit and choose Undo commit. Move the large file out of your repository folder, then commit again. Ask your lecturer if you need that file in the project.

Saved, Intermediate or DerivedDataCache folders appear in the Changes list

Your .uproject isn’t in the same folder as .gitignore. Don’t commit. Fix the layout as shown in Part 7.

After cloning, Unreal says assets are missing or can’t be loaded

Git LFS wasn’t switched on when you cloned, so you only downloaded tiny placeholder files. In GitHub Desktop choose Repository → Open in Git Bash (or Open in Terminal on a Mac), type git lfs pull and press Enter. When it finishes, open the project again.

A warning about LF and CRLF

You may see “LF will be replaced by CRLF the next time Git touches it”. This is a notice, not an error. Windows and Macs mark the end of a line of text differently, and Git is telling you it is handling the difference for you. Nothing is broken and nothing is lost. Carry on.

My commits show someone else’s name

Someone who used this computer before you left their details in Git’s settings. To fix it for this project, click Repository → Repository settings → Git config, choose Use a local Git config, and enter your own name along with the @users.noreply.github.com address from Part 2.

Commits you already made keep the wrong name. If that’s only one or two, tell your lecturer rather than trying to rewrite them yourself.

I want to undo changes I haven’t committed yet

Close Unreal. In the Changes tab, right-click the files you want to put back and choose Discard changes. They return to how they were at your last commit. This can’t be undone, so be sure.

GitHub emails me about storage or bandwidth

Your account includes 10 GB of large-file storage and 10 GB of downloads a month, which is far more than this module needs. An email means something unexpectedly large has gone in — usually Starter Content, a video, or high-detail source art.

Forward that email to vgadlecturers@rhul.ac.uk rather than ignoring it. Caught early it is quick to sort out. Left alone, the large file becomes a permanent part of your project’s history and is much harder to remove.

I can’t see .gitignore or .gitattributes on my Mac

Files starting with a dot are hidden in Finder. Press Cmd + Shift + . to show them, and press it again to hide them.
