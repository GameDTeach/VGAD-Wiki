Setting up nDisplay

How to get an Unreal project onto the LED wall in Futures Studio, with the camera tracked so the wall reacts when the camera moves.

Written for Unreal 5.7, and tested from 5.4 upwards. It uses FS_BB1 and FS_BB2 as the editor machines. Work through it in order — later parts depend on names you set earlier.

1

What you need

Check all of this is in the room and switched on before you start.

  • Unreal Engine — this guide uses 5.7, and has been tested from 5.4 up
  • FreeFileSync, for copying the project between machines
  • Editor computers — FS_BB1, with FS_BB2 as a second editor
  • Two render nodes, in the server room
  • Arri camera with Mo-Sys tracking

2

Start the render nodes

In the server room. Do this first — the nodes take a while to come up.

  1. Turn on both render nodes.
  2. Check each node's HDMI cable is connected to the Brompton processor's HDMI IN.
The cables are colour-coded

Every HDMI cable is labelled with the Brompton machine it belongs in, top or bottom.

Yellow is the render nodes. Pink is the Disguise machines. If you are following this guide you want the yellow ones.

3

Remote into the nodes

You drive both render nodes from an editor machine rather than going back to the server room.

  1. Turn on FS_BB1 and FS_BB2. This part is done from FS_BB2.
  2. Open TightVNC.
  3. When prompted, enter the IP address of one node — 10.10.10.111 for Node0.
  4. Click the New connection icon and add the other node, 10.10.10.112.
  5. Log into both nodes.
  6. On each node, open Switchboard Listener for the version of Unreal you are using. There should be a desktop shortcut.

4

Prepare the Unreal project

On FS_BB1. Plugins first, then the wall meshes.

  1. Open a new or existing Unreal project.
  2. Go to Edit → Plugins and enable Mo-Sys Livelink (the free version), Multi-User Editor and nDisplay.
  3. Unreal will ask to restart. Close the project instead — the next step adds files to it from outside the editor.
  4. Navigate to your project folder, open Content, and copy in the folder containing SM_FS_Left_Wall.uasset and SM_FS_Right_Wall.uasset.
  5. Open the project again.
  6. Delete any actors you don't need, such as PlayerStart.
Where the wall meshes live

On the FS_BB1 desktop, in FS nDisplay Asset → VP Wall meshes.

5

Add the camera

This is the camera the wall will render for. It stands in for the real Arri.

  1. Click Quickly add to the project, and under Cinematic choose Cine Camera Actor.
  2. Give it a name you'll recognise later, such as Frustum or ArriCam.
  3. Zero out its location.
Remember the name

You'll select this camera by name in Part 7, and attach tracking to it in Part 10. Naming it CineCameraActor1 will make both harder than they need to be.

6

Create the nDisplay config

The config is the asset that describes the wall: its shape, and which machine draws which part of it.

  1. In the Content Drawer click Add → nDisplay → nDisplay Config → Create New Config.
  2. Name it something that identifies the space, such as nDCFuturesStudio.
  3. Drag the config into your scene and zero out its location.
  4. Double-click the config in the Content Browser to open the nDisplay editor in its own window.
7

Config: screens and ICVFX camera

Inside the nDisplay editor. You're telling nDisplay the physical shape of the wall.

  1. Delete the default nDisplay Screen.
  2. Click Add → Static Mesh and name it Left. Add a second and name it Right.
  3. Click Add → ICVFX Camera.
  4. With the ICVFX Camera selected, search the details panel for Cine Camera Actor and pick the camera you made in Part 5.
  5. Select the Left static mesh, find Static Mesh in the details panel, and set it to SM_FS_Left_Wall. Do the same for Right with SM_FS_Right_Wall.
Watch the hierarchy

Left, Right and the ICVFX Camera must all be direct children of the Root Component.

It is easy to drop one inside the other by accident. If a mesh ends up nested under another mesh, the wall will not render correctly. Check the tree before moving on.

8

Config: cluster nodes

Now you say which render node draws which screen. Do the left side first, then repeat for the right.

  1. Click Add → Add New Cluster Node. A window appears.
  2. Under Network, enter the IP address of Node0: 10.10.10.111.
  3. Under Configuration, tick Fullscreen.
  4. Under Window, set the size to the resolution for that side — 2000 × 1400 for the left.
  5. Click Add.
  6. Select the viewport that appears (VP_0). In the details panel, under Projection Policy, change the type to Mesh, then pick the Left mesh from the dropdown.
  7. Repeat steps 1 to 6 for the right side: Node1 at 10.10.10.112, 2200 × 1400, and the Right mesh on VP_1.
If the image looks distorted

Select the Default View Point — the eye icon — and move it away from the wall. The distortion is the view point sitting too close to the mesh, not a mistake in the config.

  1. Click Compile, then save, and close the nDisplay editor.

Back in your level you should now see the VP wall standing in your environment.

9

Add Mo-Sys Live Link

Live Link is what carries the camera's real-world position into Unreal.

  1. Go to Window → Virtual Production → Live Link.
  2. Delete any sources you don't need.
  3. Click Add Source → Mo-Sys Hardware Source → UDP Mode → OK.
  4. Make sure StarTracker is selected, and give it a name.
  5. Under Tracking, enter the IP address of the machine you are working on.
  6. Click Add New Subject. If Mo-Sys is set up on the camera you'll get a green tick.
  7. Go to Presets → Save As Preset, and name it after the machine — BB1.

One preset per machine

Every editor and every render node needs its own preset, because each one has a different IP address.

  1. Click the Mo-Sys UDP source and change the IP address to the next device.
  2. Save it as a preset named after that device.
  3. Repeat until all four devices in the table in Part 1 have a preset.
  4. Go back to Presets and select the preset for the machine you are actually sitting at.
The yellow warning is expected

When you point the source at a machine you aren't sitting at, Live Link shows a yellow "invalid" warning. That's correct — the tracking data isn't arriving at this machine. Save the preset anyway.

Step 11 matters. If you leave the preset pointed at another machine, tracking will look broken on this one.

10

Attach the camera to the config

This is the step where the scene starts moving with the real camera.

  1. In the Outliner, drag your Cine Camera Actor onto the nDisplay config so it becomes a child of it.
  2. With the camera selected, in the details panel click Add and search for MoSys LiveLink Component Controller.
  3. In that component, find LiveLink → Subject Representation and set it to your StarTracker subject.
What you should see

The camera jumps to a new position. That's the point — it's now taking its position from the tracking system rather than from where you left it in the viewport.

  1. Make any remaining edits to your scene, then save and close the project.
11

Copy the project to every machine

Each render node runs its own copy of the project locally. They all have to match.

  1. With Unreal closed, open FreeFileSync.
  2. On the left-hand side, select the project folder you are copying from.
  3. On the right-hand side, select where the copy should go on the target machine.
  4. Click Compare, check the changes look right, then click Synchronise.
  5. Repeat for every node and editor machine you are using.
Close Unreal first

Copying a project while the editor has it open gives you a half-written copy, and the node running it will fail in ways that are hard to diagnose.

Any change you make after this sync has to be synced again before the nodes will see it.

12

Launch it with Switchboard

Switchboard is the control panel that starts the project on every machine at once.

Start the listeners

  1. In Unreal, click the three dots next to the Switchboard icon and choose Launch Switchboard Listener. A window opens.
  2. On any other machine being used as an editor, open Switchboard Listener for your Unreal version from its desktop shortcut.
Can't find the listener?

Same as Part 3 — it lives at [add the path to SwitchboardListener here], and it's worth making a shortcut.

Create the Switchboard config

  1. Back in Unreal, click the Switchboard icon again and choose Create Config.
  2. Under General, give the config a name.
  3. Under Devices, select the nDisplay actor you created, then enter how many editors you're using.
  4. Under Network, untick Use Localhost. Leave auto-connect ticked if you want it to find the listeners by itself.
  5. Click OK. The Switchboard window opens.

Point each device at its Live Link preset

  1. Open Settings, from the cog icon or the menu along the top.
  2. Click nDisplay in the sidebar and scroll to your node names. For each one, set LiveLink Preset to the preset you saved for that node in Part 9.
  3. Click the Unreal tab and do the same for each editor — BB1, BB2.
  4. Close the settings window.
  5. Connect every device using the plug icon.
Renaming or re-addressing a device

Disconnect all connected devices first, then click the name or IP address and type the new one. Editing while connected doesn't take.
